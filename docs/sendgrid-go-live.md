# SendGrid Go-Live: DNS + Configuration

Runbook for switching newsletter delivery from email-service/SES to SendGrid.

`EMAIL_PROVIDER=sendgrid` is a **deployment-wide switch**. It moves every project's
newsletters to SendGrid at once, not one foundation at a time. The first business
cutover is the AAIF User Community, but the switch is not scoped to AAIF. Before you
flip it, **every active From domain must be authenticated in SendGrid and listed in
`SENDGRID_AUTHENTICATED_DOMAINS`**. Today that is both `lfx.linuxfoundation.org` (the
default From) and `lfx.aaif.io` (the AAIF per-project override). A From on a domain
that is not authenticated fails the dispatcher's construction guard at startup, or is
rejected before it reaches SendGrid.

Per-newsletter provider and sender selection is future work (`LFXV2-2977`).
Per-foundation from-address (`LFXV2-2795`) and inbound reply handling (`LFXV2-2796`)
are deferred.

The exact SendGrid domain-authentication hostnames and targets are account-specific
and are generated by the SendGrid domain-auth wizard. This runbook gives the record
shape and the service wiring, not literal account IDs.

## 1. Service wiring (deploy-time)

When `app.send.provider=sendgrid`, the chart **fails the Helm render** if any of these
are missing, so stage them first (values in `lfx-v2-argocd`, secrets via
ExternalSecret). Env-var details: [`service-helm-chart.md`](service-helm-chart.md).

| Chart value to env var | Value | Notes |
| --- | --- | --- |
| `app.send.provider` to `EMAIL_PROVIDER` | `sendgrid` | deployment-wide SES to SendGrid switch |
| `app.send.sendgrid.apiKeySecretRef` to `SENDGRID_API_KEY` | (secret) | required |
| `app.send.sendgrid.authenticatedDomains` to `SENDGRID_AUTHENTICATED_DOMAINS` | `lfx.linuxfoundation.org,lfx.aaif.io` | every active From domain, exact-match |
| `app.send.sendgrid.webhookPublicKeySecretRef` to `SENDGRID_WEBHOOK_PUBLIC_KEY` | (secret) | required; drives event ingestion |
| `app.send.fromAddress` to `EMAIL_FROM_ADDRESS` | `newsletter@lfx.linuxfoundation.org` | the default From; domain must be authenticated |
| `app.send.fromAddressOverrides` to `EMAIL_FROM_ADDRESS_OVERRIDES` | `agentic-ai-foundation=newsletter@lfx.aaif.io` | per-project From; each domain must be authenticated |

> **Deployment-wide, so authenticate every From domain.** Flipping `EMAIL_PROVIDER`
> switches all projects. Enumerate every From address in play, which is the default
> `EMAIL_FROM_ADDRESS` plus every entry in `EMAIL_FROM_ADDRESS_OVERRIDES`. Every one of
> those domains must be authenticated in SendGrid and listed in
> `SENDGRID_AUTHENTICATED_DOMAINS`, or that project's sends fail.

> **Exact-domain match.** `SENDGRID_AUTHENTICATED_DOMAINS` must list each exact From
> domain. Authenticating `lfx.aaif.io` does not implicitly allow `mail.lfx.aaif.io`.
> The domain authenticated in SendGrid, the value in `SENDGRID_AUTHENTICATED_DOMAINS`,
> and the domain of each From address must be the same string.

## 2. SendGrid account configuration (in order)

Do steps 2 and 3 (domain authentication and DNS) for **each** active From domain, so
both `lfx.linuxfoundation.org` and `lfx.aaif.io`.

1. **Account off trial.** The paid plan must be active or real sends are throttled or
   blocked.
2. **Sender Authentication, Authenticate Your Domain** for each sending domain, with
   **Automated Security = ON** (SendGrid manages DKIM rotation and SPF via CNAMEs).
   This step generates the DNS records in section 3, per domain.
3. **(Recommended) Link Branding** per domain, for branded click and open tracking
   links instead of `sendgrid.net`. Produces 2 more CNAMEs per domain.
4. **Create an API key** for `SENDGRID_API_KEY`. A restricted key with **Mail Send**
   permission is sufficient. When using subusers, use a subuser-scoped key.
5. **Mail Settings, Event Webhook:**
   - **POST URL:** `https://lfx-api.<env-domain>/newsletters/sendgrid/events`
     (dev: `https://lfx-api.dev.v2.cluster.linuxfound.info/newsletters/sendgrid/events`).
   - **Events:** Delivered, Bounced, Dropped, Spam Reports, Blocked, Opened.
     (Clicks and Unsubscribes may stay off; the service ignores them.)
   - **Signed Event Webhook = ON.** The generated **Verification Key** is
     `SENDGRID_WEBHOOK_PUBLIC_KEY`. The service verifies the ECDSA signature and a
     freshness window on every event. A subuser that sends has its own webhook and key.
6. **Subscription Tracking = OFF.** The service manages its own one-click unsubscribe
   (compliance-footer link to `newsletter_unsubscribes`), so leaving SendGrid's own
   unsubscribe injection off avoids two competing mechanisms.
7. **Subusers (optional, recommended for reputation isolation).** A subuser per
   newsletter keeps each publication's sender reputation separate. Each subuser sends
   from the shared authenticated domains (associate the parent's domain authentication
   with the subuser) and has its own signed event webhook and Mail-Send key. Because
   `EMAIL_PROVIDER` is process-wide, one subuser's key is active per deployment until
   per-newsletter selection lands (`LFXV2-2977`).

## 3. DNS records (per sending domain)

Create the records below for **each** sending domain (`lfx.linuxfoundation.org` and
`lfx.aaif.io`). The shapes are identical; only the zone changes. Create exactly what
the SendGrid wizard shows (hostnames and targets contain account-specific IDs). The
`lfx.aaif.io` records are shown as the example.

**Domain authentication (step 2), 3 CNAMEs**

| Type | Host (shape) | Points to (shape) |
| --- | --- | --- |
| CNAME | `em####.lfx.aaif.io` | `u#######.wl###.sendgrid.net` |
| CNAME | `s1._domainkey.lfx.aaif.io` | `s1.domainkey.u#######.wl###.sendgrid.net` |
| CNAME | `s2._domainkey.lfx.aaif.io` | `s2.domainkey.u#######.wl###.sendgrid.net` |

**Link branding (step 3, optional), 2 CNAMEs**

| Type | Host | Points to |
| --- | --- | --- |
| CNAME | `url####.lfx.aaif.io` | `sendgrid.net` |
| CNAME | `####.lfx.aaif.io` | `sendgrid.net` |

**DMARC (recommended if absent)**

| Type | Host | Value |
| --- | --- | --- |
| TXT | `_dmarc.lfx.aaif.io` | `v=DMARC1; p=none; rua=mailto:dmarc@…` (start at `p=none`, tighten later) |

Notes:

- With Automated Security ON, SPF and DKIM are handled through the CNAMEs, so do
  **not** add a separate SPF TXT record. (If automated security is off instead, add
  `include:sendgrid.net` to the domain's SPF TXT.)
- Create CNAMEs exactly as shown. Some DNS UIs auto-append the zone, producing a
  doubled `lfx.aaif.io.lfx.aaif.io`.
- After propagation, click **Verify** in SendGrid until domain auth is green. Sends
  from a domain fail until it verifies.

## 4. Cutover + verification

1. Land the API key and webhook key as ExternalSecrets, and set values in
   `lfx-v2-argocd` for the target env, including `SENDGRID_AUTHENTICATED_DOMAINS` with
   every active From domain.
2. Flip `app.send.provider` to `sendgrid` (leaving it `email-service` keeps SES). This
   switches **all** projects at once.
3. Send a test newsletter from each active From domain and confirm: it arrives, passes
   DKIM, SPF and DMARC in the raw headers, and Delivered and Open events appear in the
   newsletter analytics (which confirms the webhook and signing key are wired end to
   end).

Rollback is a single change. Set `EMAIL_PROVIDER` back to `email-service`. The SES DNS
is untouched, so it reverts immediately.

## Blockers that depend on people outside this repo

- SendGrid account **off trial** (contract or upgrade).
- **Every active From domain authenticated** (`lfx.linuxfoundation.org` and
  `lfx.aaif.io`) with the DNS CNAMEs verified. Until a domain is green, the service
  refuses to send from it.
- The webhook route `lfx-api.<env>/newsletters/sendgrid/events` must be publicly
  reachable. The chart wires the HTTPRoute and anonymous rule automatically when
  `webhookPublicKeySecretRef` is set; confirm SendGrid can reach it.
