# SendGrid Go-Live: DNS + Configuration

Runbook for switching newsletter delivery from email-service/SES to SendGrid for
a single foundation. Scoped to the first cutover (AAIF / `lfx.aaif.io`).
Per-foundation from-address (`LFXV2-2795`) and inbound reply handling
(`LFXV2-2796`) are deferred and out of scope here.

The exact SendGrid domain-authentication hostnames/targets are account-specific
and are generated by the SendGrid domain-auth wizard; this runbook gives the
record shape and the service wiring, not literal account IDs.

## 1. Service wiring (deploy-time)

When `app.send.provider=sendgrid`, the chart **fails the Helm render** if any of
these are missing, so stage them first (values in `lfx-v2-argocd`, secrets via
ExternalSecret). Env-var details: [`service-helm-chart.md`](service-helm-chart.md).

| Chart value → env var | Value for AAIF | Notes |
| --- | --- | --- |
| `app.send.provider` → `EMAIL_PROVIDER` | `sendgrid` | the SES → SendGrid switch |
| `app.send.sendgrid.apiKeySecretRef` → `SENDGRID_API_KEY` | (secret) | required |
| `app.send.sendgrid.authenticatedDomains` → `SENDGRID_AUTHENTICATED_DOMAINS` | `lfx.aaif.io` | **exact-match**, see below |
| `app.send.sendgrid.webhookPublicKeySecretRef` → `SENDGRID_WEBHOOK_PUBLIC_KEY` | (secret) | required; drives event ingestion |
| `app.send.fromAddress` / per-project override → `EMAIL_FROM_ADDRESS` | `newsletter@lfx.aaif.io` | domain must be authenticated |

> **Exact-domain match.** `SENDGRID_AUTHENTICATED_DOMAINS` must list the exact
> From domain. Authenticating `lfx.aaif.io` does **not** implicitly allow
> `mail.lfx.aaif.io`. The domain authenticated in SendGrid, the value in
> `SENDGRID_AUTHENTICATED_DOMAINS`, and the domain of `EMAIL_FROM_ADDRESS` must
> be the same string, or the service rejects the send before it reaches SendGrid.

## 2. SendGrid account configuration (in order)

1. **Account off trial.** The paid plan must be active or real sends are
   throttled/blocked.
2. **Sender Authentication → Authenticate Your Domain** for `lfx.aaif.io`, with
   **Automated Security = ON** (SendGrid manages DKIM rotation + SPF via CNAMEs).
   This step generates the DNS records in section 3.
3. **(Recommended) Link Branding** for `lfx.aaif.io` — branded click/open
   tracking links instead of `sendgrid.net`. Produces 2 more CNAMEs.
4. **Create an API key** → `SENDGRID_API_KEY`. A restricted key with **Mail
   Send** permission is sufficient; Full Access also works for admin.
5. **Mail Settings → Event Webhook:**
   - **POST URL:** `https://lfx-api.<env-domain>/newsletters/sendgrid/events`
     (dev: `https://lfx-api.dev.v2.cluster.linuxfound.info/newsletters/sendgrid/events`).
   - **Events:** Delivered, Bounced, Dropped, Spam Reports, Blocked, Opened.
     (Clicks/Unsubscribes may stay off — the service ignores them.)
   - **Signed Event Webhook = ON.** The generated **Verification Key** is
     `SENDGRID_WEBHOOK_PUBLIC_KEY`. The service verifies the ECDSA signature and
     a freshness window on every event.
6. **Subscription Tracking = OFF.** The service manages its own one-click
   unsubscribe (compliance-footer link → `newsletter_unsubscribes`); leaving
   SendGrid's own unsubscribe injection off avoids two competing mechanisms.
7. **Subusers:** none for this cutover (single account, single domain).
   Per-foundation subusers are `LFXV2-2794`.

## 3. DNS records (zone: `lfx.aaif.io`)

Create exactly what the SendGrid wizard shows (hostnames/targets contain
account-specific IDs). Shapes:

**Domain authentication (step 2) — 3 CNAMEs**

| Type | Host (shape) | Points to (shape) |
| --- | --- | --- |
| CNAME | `em####.lfx.aaif.io` | `u#######.wl###.sendgrid.net` |
| CNAME | `s1._domainkey.lfx.aaif.io` | `s1.domainkey.u#######.wl###.sendgrid.net` |
| CNAME | `s2._domainkey.lfx.aaif.io` | `s2.domainkey.u#######.wl###.sendgrid.net` |

**Link branding (step 3, optional) — 2 CNAMEs**

| Type | Host | Points to |
| --- | --- | --- |
| CNAME | `url####.lfx.aaif.io` | `sendgrid.net` |
| CNAME | `####.lfx.aaif.io` | `sendgrid.net` |

**DMARC (recommended if absent)**

| Type | Host | Value |
| --- | --- | --- |
| TXT | `_dmarc.lfx.aaif.io` | `v=DMARC1; p=none; rua=mailto:dmarc@…` (start at `p=none`, tighten later) |

Notes:

- With Automated Security ON, SPF and DKIM are handled through the CNAMEs — do
  **not** add a separate SPF TXT record. (If automated security is off instead,
  add `include:sendgrid.net` to the domain's SPF TXT.)
- Create CNAMEs exactly as shown — some DNS UIs auto-append the zone, producing a
  doubled `lfx.aaif.io.lfx.aaif.io`.
- After propagation, click **Verify** in SendGrid until domain auth is green.
  Sends from `newsletter@lfx.aaif.io` fail until it verifies.

## 4. Cutover + verification

1. Land the API key and webhook key as ExternalSecrets; set values in
   `lfx-v2-argocd` for the target env.
2. Flip `app.send.provider` to `sendgrid` (leaving it `email-service` keeps SES).
3. Send a test newsletter and confirm: it arrives from `newsletter@lfx.aaif.io`,
   passes DKIM/SPF/DMARC in the raw headers, and Delivered/Open events appear in
   the newsletter analytics (which confirms the webhook + signing key are wired
   end to end).

## Blockers that depend on people outside this repo

- SendGrid account **off trial** (contract/upgrade).
- `lfx.aaif.io` **domain authenticated** with the DNS CNAMEs verified — until
  green, the service correctly refuses to send.
- The webhook route `lfx-api.<env>/newsletters/sendgrid/events` must be publicly
  reachable. The chart wires the HTTPRoute + anonymous rule automatically when
  `webhookPublicKeySecretRef` is set; confirm SendGrid can reach it.
